# 08｜隐私和安全：比“IP 看起来像外国”更重要

**本章结果：**你知道谁能看到什么、怎样防止凭据泄露、怎么在设备异常时撤销权限。

## 先知道谁有机会看到流量

| 参与方 | 通常可能观察到什么 | 常见误解 |
|---|---|---|
| 本地网络与接入运营商 | 与某服务器通信的时段、数据量、部分连接元数据 | VPN 不等于“没有任何痕迹” |
| 出口服务端/服务提供商 | 公网目标及部分连接元数据；非端到端加密内容可能被读取 | 不能仅靠口头“零日志”宣传判断可信 |
| 目标网站 | 账号、Cookies、设备/浏览器指纹、出口 IP、登录行为 | “出口 IP 在美国”不等于“网站认定你在美国” |
| 本机安装的软件 | 被授权访问的数据取决于操作系统权限 | 开源也需要核对下载包与更新机制 |

HTTPS 保护端到端内容，但不能覆盖所有追踪与账号风险。网络安全是多个控制叠加，不是一个开关。

## 十条必须做的动作

1. 客户端只用官网或项目维护者控制的官方 Releases；有校验码时验证安装文件。注意校验值也应从可信来源获取。
2. 云账号与重要网站开启 MFA/通行密钥，不复用密码。
3. SSH 优先密钥认证，最小化管理入口；**完成登录密钥迁移并测试成功之前，不贸然关闭密码登录。**
4. 每台设备独立连接凭据；离职、丢失或共享结束时立即撤销。
5. 不把订阅 URL、`ss://`、`vpn://`、`.conf`、二维码、私钥、SSH 密码提交到 GitHub、Issue 或 LLM 提示词。
6. 脱敏网络日志：IP、域名、手机号、路径、令牌、Cookie、账号 ID 都可能具有可识别性。
7. 把 VPN 客户端、系统和服务器纳入定期更新；先备份、确认兼容性，再升级生产设备。
8. 有隐私诉求时，理解 DNS、IPv6、WebRTC 与代理分流的区别，按实际应用测试；不依赖单页“检测全绿”。
9. 服务端限制暴露端口；不在实验服务器存放多业务客户敏感数据。
10. 确保一键退出与断开后普通网络恢复；网络恢复不应依赖继续购买某服务。

## SSH 安全的具体顺序

- 在 Mac/Linux 本地用 `ssh-keygen -t ed25519 -a 64` 生成**专用的** SSH 密钥，并设置强口令；存入系统密码管理器/硬件保护环境。
- 将**公钥**授权到服务器适当账号；别把**私钥**传到 VPS、GitHub 或聊天记录。
- 在新的终端用密钥成功登录后再考虑调整 SSH 认证策略；保持云厂商救援控制台和备用访问渠道。
- 更改 SSH 防火墙规则时先保留已建立的会话、另开终端验证，避免误把自己锁在外面。

## 发现密钥泄露了怎么办？

**先撤销，后清理。**立即在管理界面废除相应访问密钥/令牌，检查是否有未知设备、异常账单与访问记录，签发新凭据。已上传的私钥不能靠删除一条聊天或 GitHub commit 就恢复安全；要假设它已被复制。若泄露包含生产系统或个人信息，应按组织事故流程升级处置。
