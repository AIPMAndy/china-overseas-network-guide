# 25｜六种使用画像：把“默认设置”变成可复用策略

所有画像都是**参考策略**，不是可以直接粘贴进任何客户端的配置文件。界面名称、支持能力以当前软件及组织政策为准。先完成 [24 章](24-30分钟启动与一天工作流.md) 再复制。

## 画像 A：普通用户——最低复杂度

- **任务：**查看文档、通讯、日常海外网站；非连续生产工作。
- **接入：**一个来源清楚、经试用验收的授权方案 + 手机独立联网能力。
- **路由：**以按需开关为主；尽量不全局常驻，不随意叠加多个 VPN。
- **验收：**目标网站是否可打开；关闭后支付、地图、局域网是否正常。
- **恢复：**第一步关额外接入、第二步恢复系统代理和 DNS、第三步核对本地网络。
- **避坑：**安装了“客户端”并不等于已经取得网络接入服务。

## 画像 B：内容创作者——重上传与平台账号恢复

- **任务：**上传成片、发长文、访问素材、直播或连线。
- **策略：**拍摄/剪辑尽量离线；上传、发布、结算分开操作。准备本地素材副本和发布草稿。
- **优先指标：**目标平台实测上传成功率、持续上传吞吐、断点续传支持、故障恢复时间，而不是单次下载速度。
- **账号策略：**登录设备、恢复邮箱、MFA 保持可恢复；只按真实身份、所在地和平台规则申请资格，不使用虚假的地区声明。
- **备用：**预备经过批准的独立连接以及在断网时改日发布的应急方案。
- **反例：**“测速很高，所以视频永远不掉线”是错误推断。

## 画像 C：开发者——网页、终端、容器三套路径

- **任务：**Git、官方模型 SDK、包管理器、Docker 镜像、IDE 插件、API 测试。
- **策略：**明确浏览器、Shell 进程、IDE 子进程、Docker daemon/容器分别是否经代理；避免“一端成功意味着全部成功”。
- **路由：**先用系统代理或经批准的应用内设置解决简单场景；有必要且有授权时再考虑 TUN；保留内网/本地地址正确处理。
- **验收：**浏览器打开公开仓库；`git ls-remote`；包管理器访问公开索引；容器拉取一个公开镜像（视环境授权与资源情况）。
- **恢复：**移除临时环境变量、撤销测试配置，验证国内网络与公司内网。
- **可执行操作：**见 [26 章](26-Mac-Windows-终端-IDE-Docker.md)。

## 画像 D：移动端重度用户——Wi-Fi 与蜂窝平滑切换

- **任务：**手机 App、消息、iPad 协作、热点共享、移动办公。
- **策略：**每台设备单独验证；记录 Wi-Fi/蜂窝和热点三种模式，断开/锁屏/切网后复测。
- **路由：**先看官方 App 是否支持按需连接；组织托管设备遵守 MDM/Per-App VPN 管理。
- **风险：**eSIM 兼容与漫游出口是不同问题；App Store 地区、Apple ID、手机时区并不自动决定网络接入安全或服务资格。
- **操作：**见 [27 章](27-iPhone-iPad-安卓与热点.md)。

## 画像 E：小团队——可观测和可交接

- **任务：**跨境会议、客户沟通、跨国协作。
- **优先：**审批合规/客户数据处理/组织设备管理；业务联系人与网络负责人分开，定义回滚责任人。
- **主备：**来自不同故障域的连接，不用同一家服务商的两个账号冒充独立备用。
- **日志：**记录故障时间、影响、解决方案；不记录目标 URL 中的 token、Cookie 和生产数据。
- **演练：**月度一次断主线路和账号恢复模拟；RTO 根据业务实测设定。

## 画像 F：隐私敏感 / 高风险工作——先做威胁模型

- **任务：**涉及研究、敏感沟通或高价值商业数据。
- **策略：**先明确威胁来源、哪些元数据可被看到、服务商权限、终端是否可信；只用组织认可的受管理方案。
- **底线：**不宣称 VPN、Tor 或“住宅 IP”能实现不可追踪；设备被恶意软件控制时，改变出口无法保护账号。
- **失败行为：**关键任务原则上要求连接不满足安全条件时停止传输（fail closed）；其他低风险任务可选择回退直连（fail open）。分别写明，不能用一个全局开关含糊带过。

## 选错画像的三个信号

1. 你每天调整十几次规则，且无法说明每次调整解决了什么问题——复杂度超过收益。
2. 你只会看测速，无法验证最重要的三项任务——指标与实际需求脱节。
3. 你在真实业务发生异常时仍直接操作服务器和账户配置——缺少回滚和变更冻结。
