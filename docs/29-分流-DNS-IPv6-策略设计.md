# 29｜网络路由策略：分流、DNS、IPv6、TUN 与本地设备

**范围：**解释已授权方案如何制定路由策略和验证结果。具体配置字段必须以所用客户端和版本的官方文档为准，不提供未经测试的通用“神奇配置”。

## 1. 一张策略表比一万行规则更重要

| 流量类别 | 默认建议 | 为什么 | 必须检查 |
|---|---|---|---|
| 本地局域网/NAS/打印机 | 按本机与组织规则保持 LAN 可达 | 本地协作与设备发现 | 局域网路由、mDNS、访问权限 |
| 国内支付/银行/政务 | 不无故转交外部代理；符合服务规则 | 减少第三方风险与可用性问题 | 实际直连与 HTTPS 完整性 |
| 海外研发/文档/允许的 API | 用符合授权和服务条款的接入路径 | 明确任务与合法权限 | Web、CLI、IDE 各自结果 |
| 企业内网、客户系统 | 只走单位批准通道 | 访问控制、审计与数据安全 | ZTNA/企业 VPN、不可旁路 |
| 未分类服务 | 保守处理；由风险决定直连或阻断 | 防止无意泄漏/误路由 | 通过日志确认规则命中 |

## 2. 三种路由模式的实际差异

- **系统 HTTP(S) 代理：**由支持系统代理的应用选择使用，未必影响所有进程与 UDP。
- **应用级代理：**某浏览器或开发工具独立设置，仅对该应用生效。
- **全隧道/TUN：**改变更广泛的网络包路由，适用于需求明确的受控环境；需更谨慎处理内网、DNS、IPv6 与本地广播。

选择规则：需要最少时用最少；先单一应用成功，再扩展；企业设备由 IT 管理。

## 3. DNS 的五步确认

1. 查目标域名是否拼错，以及域名本身是否解析。
2. 区分操作系统使用的 DNS、客户端的解析设置、浏览器安全 DNS、企业内网 Split DNS。
3. 使用低风险域名测试，不把真实客户域名放到公共查询站提交。
4. 判断问题在 DNS 查询阶段还是已解析后的 HTTPS/TCP/QUIC 建连阶段。
5. 只有在证实某条规则有问题时才改动一处，再复测；不要直接“关闭所有 DNS 安全设置”。

**重要事实：**Cloudflare 的 Split Tunnels 文档指出，IP 路由分流和 DNS 请求策略可能分别处理。故 DNS 不是“只要分流正确就自动正确”。[官方文档](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/split-tunnels/)

## 4. IPv6 和本地 LAN 不要忽略

- 检查 IPv4 及 IPv6 访问路径是否符合公司/用户设计，避免只验证 IPv4 就宣布“不会泄漏”。
- 为远端出口关闭 IPv6 并非所有场景的最佳策略；先了解客户端与上游是否完整支持，再按安全要求处理。
- TUN 默认路由变化可能影响 NAS、打印机和设备发现；局域网白名单也会影响暴露面，不能无条件开放所有私有网段。
- 热点客户机、虚拟机、容器分别有路由表，不能假设共享主机隧道。

## 5. 安全导向的两种异常默认行为

**Fail closed（失败阻断）**：关键业务不能确定经批准的加密/受控通道时，停止其网络通信；恢复前不重新发送敏感数据。适合企业敏感数据、需要持续 VPN 策略的授权业务。

**Fail open（失败回退）**：在安全要求允许的情况下，低风险国内网站与离线工作可恢复普通网络，保证基本可用性。**不能让敏感任务在断线后意外直连**。

这两类行为按应用/任务而不是凭心情选择；在 [业务网络分层表](../templates/业务网络分层表.md) 中写下来。

## 6. 修改规则的最小变更流程

`现象 → 提出唯一假设 → 备份旧配置 → 修改一项 → 实测三个关键任务 → 保存结果 → 不满足就回滚`

示例：原来 NAS 无法发现。优先确认本机 LAN 直连与客户端本地网络权限；不要为解决 NAS 问题改动全部海外路由规则。若本地网段冲突（公司 LAN 与家用 LAN 重叠），应由网络管理员调整网络规划。

## 7. 给高级用户的检查单

- [ ] 目标域名及子域名处理符合设计，避免过宽通配符。
- [ ] DNS 路径已验证，考虑企业内网域名与分流 DNS。
- [ ] IPv4 / IPv6 的实际行为有记录。
- [ ] HTTP(S)、WebSocket、UDP/QUIC 等应用所需协议在已授权网络下可达。
- [ ] 本地服务、NAS、打印机、会议 App 正常。
- [ ] 断链时敏感任务的处理方式已明确。
- [ ] 规则命中日志仅保留必要最小信息，不记录凭据。
