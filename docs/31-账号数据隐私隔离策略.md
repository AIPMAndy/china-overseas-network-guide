# 31｜安全分层：重要账号、AI 服务、支付和客户数据

本章既面向个人创作者，也面向工作团队。**任何网络出口都不能替你提供合法账号资格、可信终端或稳定身份。**网络切换引起的登录提醒是安全机制之一，不应通过伪造住址、证件或身份绕过。

## 1. 按数据敏感度分四层

| 级别 | 例子 | 建议网络/操作方式 | 故障时 |
|---|---|---|---|
| L0 公开资料 | 官方博客、公开代码、公开论文 | 来源可信的合法网络接入 | 可换已验收备用 |
| L1 普通工作 | 一般脚本、公共素材、协作内容 | 工作专用配置与基本 MFA | 按需暂停/恢复 |
| L2 账号与商业资料 | 订阅平台、店铺后台、收款报表 | 尽量在可信设备、组织许可通道操作，验证登录与恢复 | 不进行多出口反复登录，先保护账户 |
| L3 客户机密与生产凭据 | 客户数据、密钥、财务/医疗敏感数据 | 受控设备、企业审批通道、访问权限与加密审计 | 连接不合规则停止传输 |

**使用合法 VPN 也可能面对出口运营方、DNS 提供商、终端恶意软件和目标平台的不同信任边界**。HTTPS 通常保护内容传输，但不能把它理解成所有元数据绝对不可见。

## 2. 账号本身至少做好这些事

- 每个关键平台一个独立强密码，使用可靠密码管理器。
- 优先使用平台支持的 MFA / 通行密钥；恢复码离线保管，至少安排第二种合法恢复路径。
- 不把恢复码、私钥、API Token、支付凭据写入 Git 仓库、模板、截图或 ChatGPT 提示词。
- 定期查看登录活动、第三方 OAuth 授权、SSH keys 和过期 Token。
- 网络异常时不要相信“代理客服”私信提供的解除风控链接，通过平台官方入口处理。

[GitHub 官方安全清单](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure) 建议唯一密码、2FA、密钥和授权应用核查；其 [恢复机制说明](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/recovering-your-account-if-you-lose-your-2fa-credentials) 明确恢复方法丢失可能无法找回账号。

## 3. 多设备与多角色隔离

- **日常工作机：**只运行经审查的客户端，避免测试未知安装包。
- **测试环境：**新客户端/新规则先在非生产设备或隔离的测试用户中验证；用脱敏样本。
- **企业设备：**受组织策略管理；私自修改企业代理可能破坏安全与审计要求。
- **多人共享网络：**权限按人分配、最小化、可撤销；不要把一个管理员密钥发到群里。
- **云 VPS：**SSH 密钥、最小端口暴露、自动更新策略和备份；退出供应商前注销凭据。

## 4. 指纹浏览器与“住宅 IP”常见误解

独立浏览器配置文件、不同 Cookie 容器、代理出口、系统时区是不同层次。浏览器指纹工具无法保证真实性、不可追踪性或平台认可的地区资格。不要为避免平台身份校验而伪造居住地、支付主体或使用虚假证件。

**账号运营建议**：长期维护合规、可恢复的身份资料；变更设备或网络前保存官方 MFA 与恢复渠道，重大业务操作时减少不必要的网络切换。遇到平台限制遵循官方验证/申诉机制。

## 5. 五类事件响应

| 事件 | 第一动作 | 后续步骤 |
|---|---|---|
| 订阅 URL 被公开 | 立即失效/轮换授权 | 查询服务商使用情况、通知受影响使用者 |
| 服务器私钥被公开 | 立即轮换并评估重建 | 检查日志、网络端口、系统完整性 |
| 账号被异常登录 | 走平台官方入口冻结会话、改密码 | 轮换 Token、检查 OAuth、审计财务影响 |
| 公共 Wi-Fi 安装被诱导证书 | 退出该网络，检查设备管理与证书 | 使用可信网络访问官方支持，必要时重置受影响设备 |
| 生产客户数据经不明通道传输 | 暂停传输并按公司响应流程上报 | 做风险评估、保全证据、按合同法规通知 |
