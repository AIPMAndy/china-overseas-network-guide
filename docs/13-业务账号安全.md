# 13｜做业务的人：网络连接与商业账号必须分开管理

**本章结果：**降低因网络切换、共享出口、设备权限和日志泄露带来的业务连续性问题。

## 1. 三层隔离

**网络层**：业务用途使用符合公司政策且来源可靠的接入方式，记录维护方与备用方案。避免把关键业务完全押在单个未经实测的个人节点上。

**设备层**：生产账号与实验客户端尽量不要共享管理员权限；测试新客户端前先做系统备份和安全审查。公司管理设备优先遵守 MDM/IT 政策。

**账号层**：每个重要账号独立强密码 + MFA/通行密钥 + 恢复码；不要把登录地区伪装当成账号安全手段，避免违反服务商条款。

## 2. 最低风险配置

- 针对目标业务服务，确认官方对访问地区、支付主体、服务可用性的要求。
- 客户敏感资料、源代码、token/API key 不通过不明服务商转发。
- 测试连接时使用非敏感演示数据，不使用客户生产环境。
- 若运营 X、YouTube、GitHub 等多个账号，账号归属、税务和平台资格独立管理；不能推定拥有海外 IP 就拥有海外付款、变现或账号资格。
- 做内容、直播、远程咨询时留备用网络与离线资料，避免单点故障。

## 3. 一张事故处理卡

**发生意外登录/账号锁定时：**先确认是不是官方安全警报；不要点击私信里的解封链接；通过官网更改密码、检查活跃会话、复核 MFA，按平台正式申诉流程处理。若涉及 API token 泄露，先吊销/轮换再排查费用与审计日志。

**完成凭证：**为你最重要的 3 个业务账号记录“官方恢复入口、MFA 方式、恢复码离线位置、事故联系人”，但**不要在此仓库公开真实内容**。

## 企业采购与审批

如果你是以企业主体运营海外业务，进一步阅读 [企业跨境办公方案](18-企业接入与合规边界.md)。不要把出口 IP 属性误认为平台账号资格、支付资格或所在国家的合法经营身份。
