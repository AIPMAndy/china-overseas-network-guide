# 16｜VLESS/REALITY、Hysteria 2、Trojan、Shadowsocks：怎么选

**本章结果：**看懂协议差异，在不瞎装“一键脚本”的情况下完成前置条件核查和小规模验收。

## 一分钟搞清楚

| 类别 | 传输特点 | 前置条件与约束 | 优先排查 |
|---|---|---|---|
| Shadowsocks（含 Outline） | 加密代理，生态成熟 | 选择维护中的实现与受支持密码套件 | 客户端/服务端版本、端口、探测 |
| VLESS + Xray/REALITY | Xray 生态，TLS 特征相关选项丰富 | 配置更复杂；必须核查最新官方示例 | 客户端兼容、时间同步、目标服务和证书设置 |
| Hysteria 2 | 基于 QUIC/UDP 的代理 | UDP 通路、TLS 和认证配置 | UDP 受限、运营商路径、丢包、MTU |
| TUIC | 基于 QUIC/UDP 的生态协议 | 版本与客户端实现兼容性差异 | 握手与 UDP 可达性 |
| Trojan | TLS 相关代理方案 | 必须正确验证 TLS 配置及服务端身份 | 证书、域名、SNI、版本 |
| WireGuard/AmneziaWG | UDP VPN / 衍生混淆协议 | 自建和出口地址可达；版本匹配 | 系统路由、UDP、设备密钥 |

> 这是**设计特性对照**，并非“某协议在国内成功率排名”。任何协议都不能自动赋予合法性、安全性和稳定性。

## 先做服务器前置检查（只读、安全）

1. 目标机器是**你拥有/获授权**的测试 VPS，最好为空白实例；有快照和控制台救援。
2. 明确操作系统版本、维护周期、防火墙、安全组、磁盘/带宽额度；分别记录 IPv4、IPv6 是否有可达路由。
3. 检查已有监听端口 `sudo ss -lntup`，不要抢占生产服务。
4. 检查系统时钟 `timedatectl status`、TLS 证书到期、域名控制权（若协议部署确需）。
5. 只通过官方项目安装手册选择版本；避免直接执行第三方匿名脚本。
6. 客户端先连测试账号/测试服务，保留回滚信息；再按自己的工作时段采样至少 7 天。

## Xray / VLESS / REALITY：按官方文档实施

进入 [XTLS/Xray-core](https://github.com/XTLS/Xray-core) → README → Xray-examples / REALITY 官方文档。不要从社交帖子盲抄证书字段、伪装域名、私钥。任何配置教程如果要求 `allowInsecure=true` 或跳过 TLS 验证，都要先确认版本和安全影响；**默认拒绝关闭证书校验**。各 GUI 面板常为第三方软件，额外扩大攻击面。

**验收节点**：客户端服务端版本兼容；TLS 握手成功；目标 HTTPS 真实打开；在 4G/5G 与家宽都测试；断开后恢复原网络；不出现异常新证书。失败就分类，不循环更换配置碰运气。

## Hysteria 2：UDP 是关键变量

进入 [Hysteria 官方首页](https://hysteria.network/) → Server / Client。确认服务端可接收所需 UDP，云服务商网络 ACL 不阻断；证书由可信 CA 正确签发且客户端验证开启。可以按官方教程部署到非生产 VPS，不要将带密码的配置发给任何人。不要因为“QUIC 更快”就推导出所有运营商更稳；UDP 可能受限或拥塞。

## 不建议给新手的 4 件事

- 未经审核把 3X-UI/其他面板暴露到公网，同时使用弱密码。
- 抄写过时的 VLESS / Trojan 密钥示例到公开仓库。
- 用真正业务账号验证陌生安装脚本。
- 把多种协议堆到同一个 VPS 并宣布获得“冗余”，因为机器和 IP 仍是单点。

**输出**：填好 [协议部署验收卡](../templates/协议部署验收卡.md)，不能提供任意一个客观证据的结论标为“未验证”。
