# 23｜对抗式审核：新手、工程师、安全官、事实核验员四方挑战

**本章结果：**让指南能够持续被证伪、修正和版本化，而不是靠热词和截图维持“永远稳定”的印象。

## 对抗角色 1：零基础用户

- **挑战**：只有手机、看不懂协议，可以仅靠教程完成一个合法授权配置的安装与撤销吗？
- **失败模式**：把“装客户端”误认为“获得节点”；iPhone 不支持 eSIM 却先付费。
- **验收**：新手能说清楚账户、服务端、配置、客户端四个对象；能在 10 分钟内找到对应的回滚说明。

## 对抗角色 2：网络工程师

- **挑战**：只测一台 Mac 和一个酒店 Wi-Fi，却声称适合中国全年吗？
- **失败模式**：混淆连接成功率与业务成功率；数据缺少运营商、时段、样本量；两条主备共用同一上游。
- **验收**：3 时段、2 网络、7 天的样本；至少一轮主备演练；不可实测条目必须标“待验证”。

## 对抗角色 3：安全审核员

- **挑战**：供应商如果作恶，哪里能读到你的数据？安装包会不会植入？订阅链接是否可被第三方盗用？
- **失败模式**：禁用 TLS 校验、运行未知一键脚本、上传 `.conf`、截图泄漏服务器账号、将密码写进公开仓库。
- **验收**：凭据分离、最小权限、来源核验、密钥轮换；自动扫描只是第一层，发布前人工复查。

## 对抗角色 4：合规/事实核验员

- **挑战**：是否把非经营性研究与未经许可的跨境经营混为一谈？是否把社区体验当作官方事实？
- **失败模式**：未引用法规原文；没有区分套餐宣传、社区经验、实验报告；把第三方推广号的“稳定推荐”当作调研证据。
- **验收**：高风险结论给出原始来源、核验日期和适用场景；无来源的评价只记录为假设。

## 审核总表（2026-10-12）

| 问题等级 | 发现 | 修复 | 残余风险 |
|---|---|---|---|
| P0 | 公开包含服务器凭据会造成实际入侵风险 | README、模板禁止真实密钥；脚本执行有限规则扫描 | 文件外的图片/历史提交需人工复核 |
| P0 | 可能触犯跨境经营或数据合规要求 | 分开个人学习与企业服务，引用官方政策 | 不能替代针对性法律意见 |
| P1 | 商业 VPN/机场/自建混淆 | 12 模式与五层模型 | 真实链路需供应商证据 |
| P1 | X 检索受限、营销信息污染 | 记录限制，社区材料低证据等级 | 不能得出 X 平台共识 |
| P1 | 2026 版 Amnezia 协议与中国实际兼容性不等同 | 官方标注未专门测试中国 | 中国线路仍需现场验证 |
| P1 | eSIM 在大陆的设备兼容限制复杂 | 引 Apple 原始文档并给出型号核查步骤 | 境外旅游 eSIM 需另核查 |
| P1 | 全局/TUN 给人“绝不会泄漏”的错觉 | 增加路由、DNS、IPv6、WebRTC 及回退实测 | 无法代替专业抓包审计 |
| P2 | 单次测速伪装成长期稳定 | 42 个观测点与分层 SLO | 样本量仍不足代表全年 |
| P2 | 离线网页外链及跳转可能损坏 | 自动生成、相对链接检测、资源检查 | 浏览器兼容性需人工试用 |
